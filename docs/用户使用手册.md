# CodeFlow Inspector 用户使用手册

[English](User-Guide.md) | [产品理念与技术介绍](产品理念与技术介绍.md) | [返回中文说明](../README.zh-CN.md)

## 1. 软件用途

CodeFlow Inspector 是本地桌面代码分析工具。它把一个代码项目转换为可查询的软件系统模型，帮助你回答：

- 这个项目整体在做什么？
- 主入口在哪里，数据经过哪些函数后到达结果？
- 每个文件、模块和函数分别承担什么职责？
- 哪些结论来自 AST、Compiler、LSP、真实运行或形式化证明？
- 哪些路径可能存在输入污染、权限、注入、资源或环境风险？
- 当前电脑能否承受项目运行和分析成本？
- 修改算法或代码后，性能、稳定性和安全性是否真的改善？

软件采用本地优先设计。项目源码、索引、运行记录和报告默认保存在本机；未经明确授权，知识更新功能不会连接公网。

## 2. 当前版本边界

当前版本是 **Alpha / Research Preview**。建议首先使用已脱敏、非机密项目评估。

软件会区分不同证据等级：

| 证据 | 含义 |
| --- | --- |
| Parser / AST | 解析器确认了语法结构、函数边界、参数或调用 |
| Compiler / LSP | 编译器或语言服务器确认了类型、定义、引用、宏或诊断 |
| Rule / Knowledge | 本地知识规则发现了值得检查的模式 |
| Runtime | 受控运行观察到了真实退出码、输出、异常、耗时或资源使用 |
| Test / Benchmark | 同版本测试或基准样本产生了可比较结果 |
| SMT / Proof | 求解器在明确模型边界内完成了证明或给出反例 |

高置信候选不等于已证明错误。阅读结论时应同时查看位置、触发原因、证据等级和缺失条件。

## 3. 安装与首次启动

1. 下载与你的操作系统、CPU 架构和语言对应的安装包。
2. 按系统提示完成安装并启动 CodeFlow Inspector。
3. 软件本体不要求 Pyright、JDT LS、clangd、gopls 或 rust-analyzer 才能启动。
4. 如需对应语言的跨文件深层语义，请参阅[语言工具安装指南](语言工具安装指南.md)。
5. 第一次分析建议保持公网开关关闭。

macOS 未签名预览包可能显示系统安全提示。请只从本项目 GitHub Release 下载，并在试用前核对发布页提供的校验信息。

## 4. 导入第一个项目

打开 **项目中心**：

1. 选择 **选择项目文件夹**，导入完整项目并保留文件层级。
2. 只有零散代码时，可以选择 **选择代码文件**。
3. 等待批次导入、解析和本地索引完成。
4. 在项目列表中确认文件数量、语言和更新时间。
5. 点击 **打开** 进入项目。

建议导入项目根目录，而不是只导入一个深层源码目录。锁文件、manifest、构建文件和测试目录可以帮助软件识别依赖、环境和运行入口。

### 多项目管理

- **打开**：切换当前项目，其他项目的数据不会覆盖。
- **重命名**：只修改 CodeFlow Inspector 中的显示名称。
- **复制**：创建独立项目副本，适合比较不同版本。
- **移除**：从项目库移除，并提供本次操作的撤销入口。
- **导出备份**：导出项目库元数据和可恢复内容。
- **合并恢复**：校验备份后合并，不覆盖已有项目。

不要把包含密钥、生产数据库、个人信息或专有源码的备份上传到公开 Issue。

## 5. 导航

左侧导航按四组组织：

- **项目**：项目中心、数据流总览。
- **解析**：文件解析、模块解析、函数解析。
- **实验**：问题诊断、孪生实验、测试与验证、分析报告。
- **系统**：分析内核、本地知识、设置。

### 快捷导航盘

在 macOS 上同时按住 `Command + Shift` 呼出页面选择盘：

- 移动指针或使用方向键选择页面。
- 松开快捷键进入选中页面。
- 按 `Esc` 取消。

也可以在左侧底部切换标准或紧凑导航，不会改变项目内容。

## 6. 数据流总览

**数据流总览**用于从主控入口观察主要输入、函数处理、状态变化、输出与异常路径。

图形遵循 Flow-First 布局：逻辑层级决定前后顺序，同层函数沿扇形区域排列；真实语义边保持独立，视觉共享通道不会把无关数据合并。

### 图形操作

- 拖动画布：平移视图。
- 鼠标滚轮或触控板：缩放。
- **适合**：让当前完整图形进入可见区域。
- **重置**：恢复默认视图。
- 间距与缩放控件：调整当前可读密度。
- 视图筛选：切换主线图、总览、主路径或问题路径。

点击函数节点或线路后，详情面板会显示上下游、输入输出、置信度、问题原因和证据。正常路径保持中性显示；发现断点或风险时，颜色只标记受影响节点和传播部分。

### 正确理解粗细线路

- 线路宽度表示估算的数据负载或聚合流量，不等于真实网络带宽。
- 多输入只有在真实数据语义汇合时才形成 Confluence。
- 为减少交叉而共享的视觉走廊仍保留独立 `channelId` 和完整 source-to-target 路径。
- 多输出通过 Split 和独立支路表达，不会抹除真实目标。

## 7. 文件、模块和函数解析

### 文件解析

按文件查看语言、函数、模型、职责和关联问题。适合回答“这个文件负责什么”和“问题集中在哪些文件”。点击函数名称可进入函数解析。

### 模块解析

跨文件按功能关系归纳业务域，例如入口控制、数据持久化、任务管理、调度、通知、界面状态或安全边界。模块是分析结果，不会修改原始目录。

### 函数解析

函数页提供：

- 技术位置、语言、解析器、复杂度、参数和返回值。
- 用完整文字解释函数作用、算法或处理策略。
- 上游调用、下游调用、输入输出和副作用。
- 代码树、调用流、文件层级和 FSM 等视图。
- 断点、问题传播和修复建议。

“推测的设计意图”用于帮助接手项目，不应替代项目作者文档、业务需求或真实运行验证。

## 8. 问题诊断与安全检查

打开 **问题诊断** 查看按类别归并后的问题。相同风险在多个函数出现时，会作为一个风险类型列出多个受影响位置，避免重复刷屏。

重点检查：

- 输入是否到达 SQL、命令、DOM、路径或文件操作。
- 是否存在参数绑定、白名单、身份、权限和范围检查。
- 异常、超时、重试、事务和资源释放是否完整。
- 依赖、SDK、运行时、配置、测试和硬件载体是否缺失。
- source-to-sink 路径是已净化、待验证还是确认危险。

当 Compiler/LSP、真实运行或依赖版本不足时，软件会显示“待核实”，而不是把规则模式直接写成漏洞事实。

## 9. 孪生实验与受控运行

**孪生实验**将静态模型与真实受控运行证据组合。真实执行只会在用户点击后开始。

### 推荐步骤

1. 选择语言运行器和真实入口文件。
2. 检查页面显示的工具可用性和隔离状态。
3. 勾选静态分析、动态仿真、压力测试、容错传播、算法替换、安全攻击或环境迁移。
4. 点击 **执行已勾选孪生实验**。
5. 查看进度条、当前步骤、更新时间和失败原因。
6. 检查 stdout、stderr、退出码、耗时、CPU、峰值内存、子进程和文件改动。

受控运行使用固定适配器和临时项目副本，不接受任意 shell 字符串。公网默认被拒绝。缺少运行器、入口、构建依赖或沙箱能力时，结果会显示失败、阻塞或不可用。

### 运行成本

运行成本面板估计本机内存、CPU 线程和磁盘需求。没有真实样本时，它只是规划优先级；产生运行样本后，置信度会提高。不要把估计值当作生产容量保证。

## 10. 调试

检测到对应调试适配器后，可以：

1. 在函数页设置断点。
2. 在孪生页选择入口和断点行。
3. 启动并暂停调试会话。
4. 查看调用栈、作用域和变量。
5. 执行单步、步入、步出、继续或结束。

调试失败时先检查“失败原因”，再检查 **分析内核** 中的运行器和调试适配器状态。HTTP 预览不能创建真实桌面调试会话。

## 11. 测试与验证

打开 **测试与验证**，勾选需要执行的测试泡泡：

- 功能测试
- 冒烟测试
- 回归测试
- 集成测试
- 性能测试
- 负载测试
- 可用性测试
- 修复结果验证

点击 **执行选中测试** 后，自动项目会按顺序运行；需要人工操作或修复候选的项目会记录条件，不会伪造通过。

结果分为 `passed`、`failed`、`blocked` 和 `not-run`。版本指纹变化后，旧的通过结果可能要求重新验证。

可用性测试必须由用户实际操作后逐项勾选。代码扫描不能替代人工可用性验收。

## 12. 修复候选、A/B 与安全写回

修复中心不会直接覆盖源码。推荐流程：

1. 从函数或诊断载入修复候选。
2. 检查修复理由、原文和建议代码。
3. 生成并检查 Diff。
4. 在项目副本中执行 A/B、回归、安全和基准验证。
5. 只批准当前候选哈希。
6. 点击 **安全写回**。
7. 如结果不符合预期，使用 **一键回滚** 恢复校验快照。

描述型建议如果没有生成有效代码变化，不能进入写回。预计性能提升也必须经过同输入、同环境的真实对照才能成为验证结论。

## 13. 分析报告与 PDF

打开 **分析报告**。报告包括：

- 结论摘要
- 运行成本与本机承载
- 问题和安全报告
- 孪生实验
- 测试成功、失败、阻塞与缺失条件
- 修复建议与验证状态
- 扩展接口信息

在 **设置 > PDF 报告** 中决定是否导出全部折叠证据。点击 **导出 PDF** 后，桌面程序打开系统“另存为”，由用户选择文件名和位置。报告在本机生成，不默认上传。

## 14. 分析内核与本地知识

### 分析内核

用于检查 Tree-sitter、Compiler/LSP、语言服务器、运行器、调试适配器、数据库和解析证据。`missing` 表示当前电脑未找到工具；`system` 表示发现用户安装的工具；`verified` 表示包与构建锁匹配。

### 本地知识

官方知识更新仅支持白名单来源，并经过下载、许可证、隔离、回放、签名、激活和回滚流程。公网开关关闭时不会执行在线更新。

补充知识包和扩展声明可以从本地文件导入。扩展声明只注册契约和健康检查，不直接执行包内任意代码。

## 15. 设置

- **PDF 报告**：选择是否包含全部详细证据。
- **图谱默认视图**：设置新打开图谱的节点间距和初始缩放。
- **项目证据**：跳转到孪生页产生真实运行证据。
- **网络边界**：查看当前公网策略和本地安全防御。

设置保存在本机，不发送到网络。

## 16. 推荐分析流程

```text
导入完整项目
→ 查看项目数据流和软件功能解读
→ 按文件、模块、函数下钻
→ 检查问题原因与证据等级
→ 补齐所需语言工具和运行环境
→ 执行受控运行与选定测试
→ 评估运行成本和安全路径
→ 在副本中验证修复候选
→ 审批写回或回滚
→ 导出完整 PDF
```

## 17. 常见问题

### 为什么函数数量为 0？

确认文件语言受支持且源码完整。模型类可能没有函数，但应显示声明；如果普通源码仍为 0，请查看分析内核的 AST 状态并提交最小复现。

### 为什么工具已经安装仍显示 missing？

完全退出并重启软件，在新终端中确认命令可用。具体路径检查见[语言工具安装指南](语言工具安装指南.md)。

### 为什么实验按钮不可用？

通常是没有真实入口、运行器缺失、HTTP 预览无桌面权限或已有任务正在运行。页面应同时显示阻塞原因。

### 为什么某个安全问题出现很多位置？

报告按风险类型归并，但同一模式可能影响多个函数。展开风险组查看每个位置，不应把位置数量理解为不同漏洞数量。

### 为什么图中仍有交叉？

真实大型程序可能存在跨模块、回调和循环。优先使用主路径或模块聚合视图，再放大局部。视觉共享通道不会删除真实语义边。

### HTTP 页面和桌面程序有什么区别？

HTTP 只用于界面开发和回归预览。真实文件系统、native SQLite、LSP、受控运行、调试、沙箱和系统资源检测必须在 Tauri 桌面程序中使用。

## 18. 提交反馈

普通问题请在 GitHub 创建 Issue，并提供：

- CodeFlow Inspector 版本和语言版本。
- 操作系统与 CPU 架构。
- 被分析语言和工具版本。
- 操作步骤、预期结果和实际结果。
- 最小、已脱敏的复现项目。

涉及源码泄漏、沙箱绕过、签名绕过或网络策略绕过的问题，请使用 GitHub Private Vulnerability Reporting，不要公开提交。
