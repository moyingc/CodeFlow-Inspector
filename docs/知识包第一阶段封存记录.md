# CodeFlow Inspector 知识包第一阶段封存记录

封存日期：2026-08-02
封存范围：OSV / NVD / MITRE CWE / CISA KEV 官方知识包供应链
阶段结论：第一阶段工程链已完成；知识成熟度只有在四源知识包通过质量门并激活后才显示为 60%。

## 1. 已封存能力

完整链路为：

```text
官方端点下载 -> SHA-256 原始件归档 -> 格式标准化 -> 逐记录许可证门禁
-> 未知许可证隔离 -> 四源回放校验 -> 本机 HMAC-SHA256 完整性签名
-> 人工激活 -> 原子切换 -> 上一版本回滚 -> 追加式审计记录
```

- OSV：读取修改索引并拉取指定数量的咨询记录；许可证按上游记录来源判断，未知来源保持隔离。
- NVD：按最近修改时间窗口读取 CVE 2.0，保留 CVE、CWE、CPE、CVSS 严重度和引用。
- CWE：读取官方 ZIP/XML，归一化 weakness 标识、抽象层级和描述。
- KEV：读取官方 JSON，保留已知利用优先级、加入日期、修复期限和要求动作。
- 四源必须同时存在；缺任一来源的包不能通过第一阶段回放门。
- 激活要求校验分不低于 90，且内容哈希和本机签名重新验证通过。
- 原始件和审计事件由 SQLite trigger 禁止更新与删除。

## 2. 数据库边界

本阶段新增 7 张 native SQLite 表：

| 表 | 用途 |
| --- | --- |
| `knowledge_sources` | 官方来源、许可证、归属声明和上次检查状态 |
| `knowledge_pack_versions` | 版本清单、manifest、哈希、签名和激活状态 |
| `knowledge_raw_artifacts` | 不可变官方原始件与 SHA-256 |
| `knowledge_records` | 统一后的漏洞、弱点和利用优先级记录 |
| `knowledge_validation_runs` | 格式、许可、回放和签名质量门结果 |
| `knowledge_pack_state` | 当前版本与上一版本指针 |
| `knowledge_pack_events` | 下载、封存、激活、回滚的追加式审计日志 |

运行时 Schema、Drizzle Schema 与迁移 `0024_knowledge_pack_supply_chain.sql` 已对齐。

## 3. 合法使用门禁

这个流程本身是合法的软件供应链模式，但“能下载”不等于“可任意再分发”。程序按以下原则处理：

- NVD 保留来源声明，并明确产品未获 NVD 背书或认证。
- CWE 保留 MITRE 版权、商标和 Terms of Use 标识。
- OSV 是聚合入口，逐记录继承权威上游来源；无法确定许可证的记录不进入激活集。
- KEV 作为修复优先级证据，不被解释为当前项目一定可被利用。
- 第一阶段签名是本机完整性签名，用于发现本地篡改；它不是面向公开分发的发布者签名。未来跨设备分发应升级为 Ed25519/TUF 风格签名。

## 4. 软件操作

桌面程序新增“知识包”页面。用户可以：

1. 检查四个官方源和许可证状态。
2. 导入第一阶段知识包，执行隔离、标准化、质量门和封存。
3. 查看记录数、隔离数、校验分、SHA-256 与签名有效性。
4. 手动激活已签名版本。
5. 回滚到上一有效版本。

浏览器预览不会下载、签名或激活知识数据。

## 7. 封存边界

本阶段没有宣称：

- OSV/NVD/CWE/KEV 覆盖所有软件错误。
- 静态命中等于真实可利用漏洞。
- 本机 HMAC 可以替代公开发布签名。
- 安全知识包已覆盖 SDK 版本差异、性能基准、硬件数据表和真实修复收益。

这些内容进入下一阶段，不混入本次封存完成项。
