# CodeFlow Inspector：产品理念与技术介绍

## 一句话定位

**CodeFlow Inspector 把源代码转换为可理解、可追踪、可实验的软件系统模型。**

它不是另一个只列出函数和告警的扫描器，也不是把代码上传给远程模型的聊天窗口。它希望让不熟悉代码的人理解软件在做什么，也让工程师能够追溯每条结论的技术证据。

## 为什么要做这款软件

现实中的软件理解通常被拆散在 IDE、静态扫描器、测试框架、性能工具、安全平台和文档之间。每个工具看到一部分，但接手者真正想知道的是完整故事：

> 数据从哪里进入，经过什么处理，在哪里改变，为什么出现风险，换一种实现会带来什么代价？

CodeFlow Inspector 的出发点，是把代码理解从“阅读文本”推进到“观察系统”。程序被建模为输入、函数、状态、存储、异常和输出组成的网络，再把静态事实、运行证据、安全规则、实验结果和修复记录放回同一个上下文中。

## 从代码到程序数字孪生

```text
Source Code
→ AST / Compiler / LSP Facts
→ Semantic Program Graph
→ Control and Data Flow
→ Controlled Runtime Evidence
→ Program Digital Twin
→ Test, Optimization, and Repair Decisions
```

这个过程的核心不是生成更漂亮的图，而是建立一份可以追问“依据是什么”的软件模型。

## 核心理念

### 1. 同时服务两类读者

面向非工程用户，软件用完整、分段的功能解读说明项目、模块和函数在做什么。面向工程师，保留代码位置、参数、返回值、复杂度、类型、调用、source-to-sink、运行成本和证据等级。

通俗表达与技术标注来自同一结构化事实，避免出现两套互相矛盾的解释。

### 2. Flow-First 数据流可视化

项目图以数据的逻辑前后关系为第一约束。入口位于高位，输出沿主轴向外展开；相同 flow depth 的函数位于同一径向层，模块与分支占据独立扇区。

布局会根据节点密度扩大层内角宽，根据线路、汇流、分流和路由压力调整相邻层间距。真实函数位置冻结后，路由器只调整虚拟汇流、分流、路点和多车道共享走廊。

最重要的原则是：**视觉整理不能修改代码语义。**只有真实数据汇合才创建 Confluence；仅为减少交叉而共享路径时，每条 semantic edge 仍保留独立 channel、顺序和 source-to-target trace。

### 3. 证据优先，而不是结论优先

软件把 Parser、Compiler/LSP、本地规则、运行样本、测试、benchmark 和 SMT 证明分开标注。规则命中是检查线索，运行观察是样本事实，证明只在明确模型边界内有效。

这让用户能看到：

- 为什么节点或线路被标记。
- 哪段代码触发了结论。
- 结论当前有多可靠。
- 还缺什么证据。
- 应该如何验证或修复。

### 4. 本地知识与 DeepWeb 证据融合

本地知识库覆盖语言 API、算法、复杂度、性能、安全、稳定性、环境、依赖、硬件边界、故障模式和修复配方。

DeepWeb 不是通用大语言模型，也不替代编译器或证明器。它是面向代码分析任务的本地多维证据融合与排序内核：把代码特征、图结构、规则命中、环境、历史实验和修复结果映射到候选风险与优先级，并保留老师证据、置信度与训练门禁。

候选结果不会因为分数高就自动进入稳定知识。没有高可信证据或修复回放的结果保持为候选，避免软件在没有反馈时自我强化错误。

### 5. 程序数字孪生

静态分析告诉我们代码可能如何工作，受控运行告诉我们某次输入下实际发生了什么。数字孪生把二者组合，用于：

- 动态仿真与极端输入。
- 容错与失败传播。
- 算法替换对比。
- 性能、稳定性和资源占用权衡。
- 安全输入与权限断言。
- 环境迁移和硬件约束检查。

没有真实运行样本时，实验会明确标记为模型或估计；不会把预测性能伪装成 benchmark。

### 6. 修复不是一句建议，而是一条可回滚工作流

修复候选经历精确原文、建议代码、Diff、项目副本 A/B、回归与安全门禁、用户审批、哈希绑定写回和一键回滚。

目标不是追求单一的“最快”，而是在性能、稳定性、安全性、资源成本和维护性之间寻找适合当前项目的方案。

### 7. Local-First 安全边界

CodeFlow Inspector 是本地桌面软件，不依赖 localhost 服务来完成核心工作。Tauri IPC 连接界面与 Rust 本机内核，项目和证据写入本地数据库。

公网默认关闭。知识更新只允许明确授权的白名单来源；受控运行使用固定适配器、临时项目副本、资源上限、子进程清理和操作系统隔离能力。报告在本机生成。

## 已有技术构成

### 桌面与界面

- Tauri 2 本地桌面壳与 IPC。
- React 19、Next.js 16、TypeScript 和 Vite 桌面构建链。
- 中英文独立发行构建。
- 多项目隔离、备份、恢复和 native SQLite 数据持久化。

### 解析与程序图

- Tree-sitter 多语言 AST：TypeScript/JavaScript、Python、Java、C/C++、Go、Rust、C#、Kotlin、PHP、Ruby、Swift、Shell 和 SQL 等。
- TypeScript Compiler 桥和可选 LSP 适配链。
- Pyright、JDT LS、clangd、gopls、rust-analyzer 的系统/受管工具检测。
- 函数、调用、控制流、definitions/uses、source-to-sink、别名、堆对象和有界并发模型。
- Adaptive Flow-First Fan Layout、多车道共享走廊和局部 crossing repair。

### 分析、知识与验证

- 数学、算法、效率、安全、稳定、语言 API、环境、硬件和修复配方的本地知识结构。
- 确定性的规则引擎与 DeepWeb 多维证据融合。
- CVE/CWE/KEV/OSV 知识包的许可证、隔离、签名、激活和回滚供应链。
- 本地 Z3 项目契约批处理接口；只有真实 solver 记录才标为证明证据。
- 风险归并、source-to-sink 安全路径和动态边界分析。

### 运行、测试与修复

- Node.js、Python、Java、Rust、C 和 C++ 固定适配器受控运行。
- stdout/stderr、退出码、耗时、CPU、峰值内存、进程树和文件改动记录。
- DAP 调试会话与断点、调用栈、作用域和变量接口。
- 功能、冒烟、回归、集成、性能、负载、可用性和修复验证编排。
- 候选 Diff、A/B 回放、安全写回和校验快照回滚。
- 本地结构化 PDF 报告。

## 与常见工具的区别

| 常见工具 | 主要回答 | CodeFlow Inspector 的补充 |
| --- | --- | --- |
| IDE / Code Browser | 定义在哪里、谁调用它 | 把调用放回完整数据路径、模块职责和证据上下文 |
| 静态扫描器 | 哪些模式可能危险 | 同时展示传播路径、证据等级、缺失条件和运行验证 |
| 性能分析器 | 某次运行哪里慢 | 将运行成本与算法替换、稳定性和修复 A/B 关联 |
| 架构图工具 | 系统结构看起来怎样 | 从代码事实生成，并允许下钻到文件、函数和 source-to-sink |
| 远程 AI 助手 | 用自然语言解释代码 | 本地运行，保留确定性证据，不要求上传项目 |

它不试图替代所有专业工具，而是把分散证据组织成一份可理解、可验证的软件系统视图。

## 适用场景

- 接手陌生或缺少文档的代码库。
- 向非开发人员解释软件功能与风险。
- 审查数据从外部输入到敏感出口的传播。
- 为重构、算法替换和环境迁移建立实验依据。
- 在写回源码前验证候选修复。
- 为安全、测试和维护讨论生成可追溯报告。
- 教学中同时展示程序结构、数据流和证据边界。

## 不是什么

- 不是能够保证发现所有漏洞的认证安全产品。
- 不是通用大模型，也不把候选预测当成事实。
- 不是在所有语言和动态机制上都无限精确的形式化验证器。
- 不是无需测试即可自动修改生产代码的机器人。
- 不是云端托管代码仓库。

反射、运行时代码生成、FFI、宏、跨语言内部传播和真实并发仍可能需要动态轨迹或专业工具补证。

## 当前发布定位

当前版本适合作为公开的非商业 Alpha / Research Preview，用于收集真实项目中的布局、解析、证据质量、运行兼容性和工作流反馈。

它已经形成完整的桌面产品主链，但成熟度来自持续验证，而不是功能名称数量。欢迎提交最小、脱敏、可复现的样本，帮助改进语言适配、图形路由、故障语料、benchmark 和修复回放。

## 愿景

我们希望代码分析不再只给工程师一串告警，而是给每个参与软件的人一张可以探索的系统地图：

> 看得懂它在做什么，追得到数据往哪里走，分得清事实与推测，也能在真正修改之前看见代价。
