# 运行成本、扩展接口与 GitHub 发布准备封存

[English](Runtime-Cost-Extension-API-GitHub-Preparation-2026-08-23.md)

日期：2026-08-23

## 本轮目标

1. 判断当前导入项目在本机上的 CPU、内存、磁盘和进程压力。
2. 为后续语言、嵌入式、前端、知识、测试和报告能力保留简单导入入口。
3. 在不泄露本地项目数据的前提下准备 GitHub 反馈流程。

## 运行成本

- Tauri 新增只读 `codeflow_system_capacity` 命令，通过 `sysinfo` 读取逻辑 CPU、总内存、可用内存和本地数据卷可用空间。
- 项目成本由文件、函数、数据边、源码字节和受控运行记录联合计算。
- 受控运行存在时，使用真实 CPU 时间、峰值内存和子进程树校准；没有运行样本时明确标为静态估算。
- HTTP 预览没有本机内存/磁盘权限，因此必须显示“待测本机”，不能宣称电脑余量充足。
- 完整报告 PDF 已包含预计峰值内存、线程、磁盘、证据等级和降低成本建议。

## 扩展导入

- 知识数据继续走补充证据包的 native SQLite 隔离、哈希、签名重放、激活链。
- 新增 Adapter Contract 1.0 声明导入和模板下载。
- 声明包仅能注册输入、输出、健康检查和隔离方式。
- `command`、`script`、`binary`、`executable`、shell/install hook 等字段被拒绝。
- 实际可执行 sidecar 仍需单独的签名安装、健康检查和沙箱门禁。

## GitHub 反馈准备

- 添加 Bug Report 与 Feature Request 表单。
- 添加 Pull Request 检查模板。
- 添加 `CONTRIBUTING.md` 与 `SECURITY.md`。
- 安全漏洞必须走 GitHub Private Vulnerability Reporting，禁止把本地源代码、数据库、密钥、私有路径和运行输出放进公开 Issue。
- 现有 GitHub Actions 会在 macOS、Linux、Windows 构建中英文桌面包并运行受控运行验收。

## 验证

- `npm run build`：通过。
- `npm test`：84/84 通过。
- `cargo check --locked`：通过。
- `npm run lint`：0 error；保留 10 条既有未使用代码 warning。
- HTTP 桌面宽度视觉复核：运行成本和扩展导入区域无文字溢出。

## 发布前仍需人工决定

- GitHub 仓库名。
- 公开或私有。
- 软件许可证。没有许可证时，公开源码默认不授予他人复制、修改或分发权利。
- 安全报告的接收账户与最终仓库 URL。
