# 数据路径汇聚视图设计记录（2026-08-14）

## 共同语义底座

主线视图和冲积扇视图只改变表现层，不改变代码语义层。真实函数调用、参数、返回值、状态依赖、异常边和 source-to-sink 路径始终保存在同一份精确图中。

## 版本 A：主线视图

- 定位：正式主线版本，用于快速阅读大型项目的整体骨架。
- 相同处理深度的数据边按区域聚合为走廊。
- 多条细分支先汇入按通量计算宽度的主干，再从主干分流到目标节点。
- 默认不绘制全部精确边；“全部”和“问题”视图可查看精确关系。
- 优点：节点少、线短、总览清晰，适合快速理解主控流程。
- 局限：弱化了虚拟地形与层级高低关系。

## 版本 B：冲积扇视图

- 定位：实验视图，用于观察层级、汇聚、分流和容量变化。
- 从左上高位输入向右下低位输出排列。
- 左上角附近使用同一个虚拟圆心；每个处理层级使用一条由左上向右下扩张的同心扇形圆弧约束节点位置，不渲染圆弧或地形背景。
- 虚拟圆弧只参与布局计算，不在画布中渲染。
- 层内函数沿圆弧按稳定拓扑顺序分布；圆弧半径随该层函数数量和点击间距自动扩大。
- 第 1 层位于左上高位，后续层级沿半径逐圈向右下扩张，形成严格的 `1 -> 2 -> 3 -> ... -> n` 视觉顺序。
- 主入口固定为 `Level 0`；其后函数按照从入口实际经历的最长前向路径进入 `Level 1...n`，闭环和回调不用于抬高主层级。
- 普通计算与业务函数位于整数层圆弧附近；解析、转换、适配节点位于相邻两层之间约三分之一处，队列、缓存、状态和持久化节点位于约五分之三处。
- 相邻圆弧之间也是有效虚拟地形。路由器可在层间带中调整端点、切换径向或切向通道，并在进入下一层前完成局部汇聚与分流。
- 真实语义边即使从第 1 层调用第 n 层，也必须经过每个中间圆弧上的隐形路由点；这些点只约束走线，不伪造函数或调用关系。
- 每个扇形层内部包含不可见的局部流域通道：层级通道负责跨层传递，区域主干负责模块内部流量，函数支路只在节点附近接入，同层关系沿局部环形通道行走。
- 函数先按上下游重心进行双向扫描排序，再通过相邻交换最小化跨圆弧的逆序关系；只有能减少线路交叉的交换才会被保留。
- 每个函数在表现层只保留一个入口和一个出口。
- `a -> b、c -> b、d -> b` 在 `b` 的入口外汇成一条主干后进入函数。
- `b -> e、b -> f` 先由 `b` 的单一出口离开，再在函数外分成两条支流。
- 粗线只能与函数入口或出口相邻，不允许在两组函数之间凭空生成公共粗线。
- 分流主干从函数出口以聚合宽度开始，每分出一条支流后逐段变细。
- 汇聚主干从细线开始，每加入一条支流后逐段变粗，最后只保留一条粗线进入函数。
- 底层通量严格满足 `Q = sum(qi)`；显示宽度使用 `W = 基础宽度 + 系数 * sqrt(Q)` 压缩，既保留粗细关系，也避免大型项目主干遮住节点。
- 大项目按处理深度和纵向区域切成多条走廊；当前采用更宽的层距、行距和路径避障间距，避免所有关系挤入同一中心点。
- 路径分配使用点到线段距离检查函数障碍，并通过分轨扫描为相互干扰的路径选择不同通道。
- 无关线路交叉是硬约束。路由顺序依次为：交换层内函数顺序、切换层内通道、沿功能域外缘绕行、扩大扇形间距，最后才允许显示明确的跨线桥；只有真实语义汇聚可以相交并合流。
- 每条线路穿越虚拟圆弧时使用独立路由缺口，弧线上不允许无关线路交叉或被误读为连接。
- 冲积扇精确路径使用逐层 Catmull-Rom 转三次贝塞尔曲线；曲线从内圈逐层进入外圈，不再以一条长线跨越多个处理层级。
- 大型项目缩小时显示功能域聚合，中等缩放显示模块主干和关键函数，放大后显示全部函数与局部支路；语义数据始终完整，仅改变显示精度。
- 缩小总览中每个功能域最多保留一条主要入口和一条主要出口；模块缩放再展开聚合节点的其他关系，细节缩放显示全部精确边。
- 缩小总览不是精确边的缩小版。它使用无环、单主上游的有向骨架：每个函数只选择一个主上游进入全局主河道，其余真实输入与输出归入模块层的局部支流。
- 总览骨架只保留 `Level 0` 入口、主流程节点和功能域汇聚口。普通函数不以长距离独立连线进入总览，避免多输入、多输出把全局主干重新拆成线团。
- 总览先确定主河道，再安排函数端点；同一主干的后代占用连续扇区。线路使用靠近端点的短曲线连接，不再为了避让沿多个圆弧做大范围绕行。
- 模块层恢复关键函数和短支流，细节层恢复全部精确调用。被折叠的边必须能从汇聚口或节点详情追溯，不能因为总览简化而丢失语义证据。

## 视图切换

- `主线图`：版本 A，默认视图。
- `冲积扇`：版本 B 的函数调用尺度；显示关键函数调用、局部汇聚和多输入/多输出支流，放大后可进入全部精确调用。
- `全部`：完整项目的冲积扇总览；显示入口、主要处理节点和功能域汇聚口组成的全局骨架，不把 64 条精确边直接压到一张小图上。
- `主路径`：只显示标记为 `primary` 的主要关系及其端点函数，不混入诊断边、闭环边或无关函数。
- `问题`：只看受诊断影响的节点和路径。

## 验收规则

1. 切换视图不得改变函数、边、诊断或证据数量。
2. 无关路径不得因为视觉交叉而被表达成汇聚。
3. 每个函数在冲积扇表现层最多显示一个入口干线和一个出口干线。
4. 控制栏必须占据独立区域，路径和节点不得被控制栏遮挡。
5. 点击聚合走廊必须能回到其代表边和精确证据。
6. 无关线路交叉数、线路穿过无关函数数和函数框重叠数应为零；若图论上无法平面化，必须使用明确桥接符号而不是伪装成汇聚。

## 最终模型修订：Adaptive Flow-First Fan Layout（2026-08-22）

本节覆盖前文中“统一层间距”“函数数量直接改变圆弧半径”以及“单个函数位于整数层之间”的旧描述。

- `flowDepth` 只确定逻辑层级和径向先后顺序；同一 `flowDepth` 的所有真实 Function 始终共享同一个 `layerRadius[d]`。
- 半径使用累积模型：`radius[0] = baseRadius`，`radius[d + 1] = radius[d] + spacing[d]`。
- `spacing[d]` 按每一对相邻层单独计算，不允许使用全图统一放大系数。
- `nodePressure[d]` 由本层节点实际宽度和最小点击间隔组成，只决定 `angularSpan[d]`、角序和局部角间距。
- `routingPressure[d]` 由跨层 Edge、加权 Confluence/Split、通道需求和结构性交叉估计组成，只决定 `spacing[d]` 与 Routing Strip 宽度。
- 每个 `spacing[d]` 都受 `minSpacing / preferredSpacing / maxSpacing` 约束。节点少且线路少的层使用 preferred spacing，禁止形成无意义长尾。
- 高密度层只扩大本层扇面；高线路压力只扩大对应层间 Routing Strip。任何单个 Function 都不能通过径向偏移解决碰撞或交叉。
- 真实 Function 完成层级半径、角域、角序和碰撞校正后立即冻结。后续阶段只能创建或移动 Virtual Confluence、Virtual Split、Shared Channel、Waypoint 和 Channel Corridor。
- Virtual Terrain 被严格定义为 Layer-local Routing Potential Field，只参与边的几何选路，不参与 `flowDepth`、`layerRadius` 或 Function 坐标决策。
- 路由低成本区域包括径向前进、同分支/同 basin、现有 Shared Channel 和主轴走廊；高成本区域包括 Function 障碍、无关分支核心、不兼容通道、交叉热点和径向回退。
- 结构性交叉的处理顺序固定为：层内角序、兄弟分组、分支连续性、Virtual Confluence/Split、Shared Channel、Routing Corridor、Potential Field、交叉检测、局部重路由。
- 普通长 Edge 必须逐条 Routing Strip 前进。跨越多个层级或角向距离过大的关系优先使用共享主干和局部 waypoint，直接长曲线仅作为最后回退。

最终职责边界：Flow 决定前后，Density 决定扇面宽度，Routing Pressure 决定局部层间距离，Router 决定路径走向。

### 函数框重叠修复验收（2026-08-22）

- 层内所需弧长现在使用实际函数图形直径、诊断标记和可点击净空共同计算，不再只统计 Function 数量。
- 高密度层达到最大可读角宽后，扩大整个 `layerRadius[d]`，并将新增半径累积到所有后续层；不移动任何单独 Function 到其他层。
- 相邻层的基础间距按最大节点直径加路由净空计算，Edge、汇流、分流和预计交叉压力只增加对应 `spacing[d]`。
- basin 内部排序完成后执行全层碰撞校正，跨 basin 边界也必须满足两个节点半径与点击净空之和。
- 在当前 28 个可见节点的大项目冲积扇回放中，修复前发现 3 组框距不足；修复后自动量测为 0 组。

### Edge-only Routing 冻结版本（2026-08-22）

- Real Function 坐标在进入路由阶段前使用冻结副本，Edge Router 不得修改 `x / y / depth / fanRadius / fanAngle`。
- 每个跨层关系按顺序经过对应的 Layer-local Routing Strip；跨多层边会生成连续视觉 waypoint，不再默认使用一条跨扇面长 Bézier。
- Shared Channel 聚类同时检查角度相似、来源或目标 basin 一致以及径向区间重叠；聚合只改变表现层，每条真实 Semantic Edge ID 仍可追溯。
- Virtual Confluence 提前放入目标层之前的 Routing Strip，Virtual Split 提前放入来源层之后的 Routing Strip，避免在 Function 框旁突然汇聚或分流。
- 初次路由完成后执行最多四轮局部修复，只重算参与交叉、穿框或异常绕行的 Edge；其他已接受路径和全部 Function 坐标保持不变。
- 路由硬约束按穿过 Function、无关线路交叉、径向回退、长距离绕行、急转弯依次计入高代价；共享通道和径向前进获得奖励。
- 当前项目 WebView 回放：28 个 Function 坐标变化 0；3 条 Shared Channel 覆盖 7 条真实关系；5 条边完成局部重路由；无关 Function 穿越 0；剩余结构性交叉候选 2 条。

### Multi-Lane Shared Corridor 语义隔离契约（2026-08-22）

本节覆盖前文中“共享主干”“点击聚合走廊代表边”等可能造成语义合并误解的描述。

- 视觉 bundling 绝不执行 semantic merge。只有代码语义层证明多路数据真实进入同一处理点时，才允许创建 `VirtualConfluence`；只有同一真实输出产生多个下游时，才允许创建 `VirtualSplit`。
- 多条无关 Semantic Edge 需要共用几何路线时，使用 `Multi-Lane Shared Corridor`。Corridor 只是不可交互的浅色路由包络，不代表任何数据边。
- Corridor 内每条 Semantic Edge 保留独立 `channelId`、稳定 `laneOrder`、`sourceId`、`targetId` 和完整 source-to-target 路径；不得用代表边替代其他成员。
- 每条 lane 拥有独立可点击热区、诊断等级、颜色、方向标记和详情浮窗。选中 lane 时只高亮该语义边及其两个端点，其他 lane 降为背景。
- Function 使用 Input Gateway 与 Output Gateway 收束视觉接口；Gateway 后仍保存全部独立 semantic lanes，不得把“接口聚合”解释为“数据已经汇合”。
- 真实 Function 坐标继续保持冻结。Multi-Lane Corridor、Gateway、Confluence、Split 和局部 crossing repair 均只能修改虚拟路由对象。
- 固定执行顺序为：`FlowDepth -> Layer Radius -> Layer-local Function Ordering -> Freeze Function -> Gateway / Confluence / Split -> Multi-Lane Corridor Routing -> Local Crossing Repair`。
- 当前 WebView 验证：3 个 Multi-Lane Corridor 包含 7 条独立 lane；7 个 `channelId` 全部唯一；旧单一共享粗干线为 0。
